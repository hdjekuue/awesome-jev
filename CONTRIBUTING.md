# Contributing to Awesome Jev

Thanks for adding your project. This list is **generated from one data file**, so a
contribution is smaller than it looks — and it lands in all three languages at once.

**English** · [中文](CONTRIBUTING.zh.md) · [Français](CONTRIBUTING.fr.md)

## The 60-second version

1. Fork and create a branch: `git checkout -b add-your-repo`
2. Add one object to `data/entries.json` (schema below), in all three languages
3. `node scripts/verify.mjs` — must pass with 0 errors
4. `node scripts/build-readme.mjs && node site/build.mjs` — regenerate
5. Open the PR using the template, title `Add owner/repo to Category`

That's it. The README tables, all three languages, the website and the machine-readable
exports are regenerated by CI as well, so if you forget step 4 the bot will do it.

## Why the data file

`README.md`, `README.zh.md`, `README.fr.md` and `docs/` are all generated from
`data/entries.json` between the `<!-- entries:start -->` markers. Editing a README table by
hand means the three languages slowly disagree, which is the single most common way awesome
lists rot. Edit the data instead.

## Schema

```jsonc
{
  "id": "owner--repo",              // slug: owner and repo, lowercased, "--" between
  "name": "owner/repo",
  "url": "https://github.com/owner/repo",
  "kind": "repo",                   // "repo" | "resource"
  "description": "One English sentence, 20–240 characters.",
  "descriptionZh": "一句简体中文。",
  "descriptionFr": "Une phrase française.",
  "category": "coding-agents",
  "language": "TypeScript",
  "license": "MIT",
  "stars": 1234,                    // number for kind="repo"; use null for resources
  "forks": 56,
  "topics": ["jev", "agent"],
  "official": false,
  "archived": false,
  "pushedAt": "2026-09-24",
  "intents": ["gate or approve tool calls before they run"]
}
```

### Description rules

- One sentence, factual, no marketing adjectives ("blazing fast", "revolutionary").
- Start with a capital letter, end with a period.
- Keep product names, repo names, CLI flags and API paths in Latin script in all languages.
- Say what it does, then what it costs you in latency or dependencies if that's the point.
- 20–240 characters. `verify.mjs` warns outside that range.

## Admission criteria

1. **It calls Jev.** The System One endpoint, an official SDK, or a documented replica of the
   System One interface. Mentioning Jev in a list does not count.
2. **It is public and legible.** Public repo, README that says what it does.
3. **It runs.** No stubbed API call with no code behind it.
4. **It is not already listed.** One repository, one entry.
5. **It is not archived.** (Archived entries stay listed but are marked `archived: true`.)
6. **Nothing shady.** No credential harvesting, no obfuscated payloads, no phoning home
   beyond documented APIs.

## What happens after you open the PR

| Stage | What runs |
| --- | --- |
| `verify` | `node scripts/verify.mjs` — schema, duplicates, categories, description length |
| `site` | regenerates READMEs, `docs/`, `llms.txt`, `projects.json` |
| `curator` | a **free** model verifies the repo calls Jev, checks for duplicates, writes a review comment |
| `gate` | a second, independent free model approves, requests changes, or closes |

A maintainer (or the gate) merges. If nothing happens in 48 hours, leave a friendly ping.

## House rules

- **One entry per PR.** Bundling gets closed so reviewers can actually review.
- **Recommending someone else's project is always welcome** and is not subject to the
  self-promo limit below.
- **Self-promo velocity is capped.** Rapid self-submissions (your own repositories, several
  in a short window) get a friendly note first, then reminders, then auto-close. See
  [`.github/curator-policy.yml`](.github/curator-policy.yml). This is about review capacity,
  not about who you are.
